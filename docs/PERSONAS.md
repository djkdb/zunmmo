# LIFE RPG — 페르소나 & 시뮬레이션

> 베타 전, 실제로 쓸 사람 5명을 정하고 **앱을 그 사람의 하루대로 직접 플레이**해 마찰을 찾았다.
> 시뮬레이션은 `e2e/personas.spec.ts`에 남아 있고, 이제 각 여정이 "고친 것"을 단언하는 회귀 테스트다.
> 여정마다 스크린샷과 화면 텍스트가 `test-results/personas/<id>/`에 저널로 쌓인다.

## 2. 시뮬레이션 방법

- **세계 구성** (`e2e/world.ts`): 프로필(시간대·하루 용량), 퀘스트·퀘스트라인, 일정, 과거 플레이를 DB에 직접 만든다. XP는 진짜 `complete_quest` RPC로 쌓고 날짜만 과거로 옮긴다.
- **시각 고정**: 플레이어 시간대를 `Etc/GMT±N`으로 정해 "지금 로컬 01시"(P1)·"10시"(나머지)를 언제 돌려도 재현한다 (`zoneAtLocalHour`).
- **플레이**: 실제 앱을 Playwright로 조작 — 대시보드 확인 → 오늘의 모험 시작 → 편집·완료·되돌리기. P5는 `prefers-reduced-motion`, 키보드 Tab/Enter만 사용.
- **관찰**: 단계마다 화면 텍스트와 스크린샷을 저널로 남기고, 페르소나의 기대와 어긋나는 지점을 찾았다.

## 6. 4주 시뮬레이션 — 발견 → 개선

규칙 위에서 다섯 명의 4주를 돌린 결과([SIMULATION](./SIMULATION.md))가 밸런스 문제 세 가지를 드러냈다.

| 발견 (1차 실행) | 개선 | 2차 실행 |
|---|---|---|
| **아무도 1주차에 레벨업하지 못함** (첫 레벨업 9–17일째, 하늘조차 9일째) — 목표는 "첫 주 1–2회" | 레벨 곡선 **램프**: 300 → 400 → … → 레벨당 1,000 (Lv.9부터). 모든 단계 ≤ 1,000이라 기존 플레이어 레벨은 오르기만 함 | 전원 1주차 레벨업 1–2회, 첫 레벨업 2–7일째 |
| **하늘의 루틴 8개 중 매일 같은 2개(저녁 약·일기)가 추천에서 빠짐** — 6개 상한 + 만든 순서 동점 처리 | 습관은 단발 6개 상한 밖, 예산 안에서 더함 (계획 최대 12개, DB 제약 변경) | 하루 추천 6 → 8개, 루틴 전부 |
| **새벽형 지민은 평일마다 가벼운 계획**(하루 1.4개) — 새벽 1시가 그의 "오후"인데도 | 심야 = **하루 시작 시각 전 4시간**. 3일 이상 심야에 플레이하면 GM이 하루 시작 시각 변경을 안내 | 팁을 따른 2주차부터 평일도 일반 계획 (P1 여정에서 팁 확인) |

불변식(결정적, XP 감소 없음, 플레이 가능한 추천만, 주 N회 상한, 예산, 말과 계획 일치, 준비 전 보스 금지)은 매 실행에서 검사한다.

### 6.2 적극 플레이 — 앱 기능이 실제로 도움이 되나

| 발견 (적극 플레이 1차) | 개선 | 결과 ([SIMULATION](./SIMULATION.md)) |
|---|---|---|
| **지민이 동아리 회의록을 28일 동안 24번 뺌** — GM이 뺀 퀘스트를 다음 날(같은 날 "다시 추천받기"에도) 그대로 다시 추천 | **뺀 퀘스트는 쉰다**: 습관은 그날, 단발은 이틀 더 (`SNOOZE_DAYS`, `adventures.removed_quest_ids`). 내일 마감이면 예외 | 24번 → 9번. P2 여정: 헬스를 빼고 다시 추천받아도 돌아오지 않음 |
| **소연이 다시 도전한 포트폴리오(90분)가 끝내 추천되지 않음** — 하루 120분이라 "너무 큼" 안내도 없지만, 매일 습관 50분 옆에는 영영 안 들어감 | tooBig을 **매일 습관이 남기는 시간** 기준으로, 마감 있는 퀘스트 전부로 확대 (주 N회 습관은 옮길 수 있어 제외) | 소연 적극: 나누기 1·다시 도전 2, 미완 마감 1 → 0 (늦게라도 끝냄), Lv.2 → Lv.3 |
| 첫 수정 후 **현우가 같은 퀘스트를 세 번 쪼갬** — 주 3회 헬스(70분)까지 "매일 습관"으로 세서 40분 단계도 너무 크다고 함 | 매일(`freq: daily`) 습관만 센다 | 나누기 1번(2시간 → 40분 ×3)으로 출시 퀘스트라인 클리어 (수동은 4주 내 클리어 못 함) |

나누면 XP 총합은 원래와 같거나 약간 적다 (지민 1,710 → 1,650) — 쪼개기는 농사가 아니라 끝내기 위한 도구라는 규칙(§1.3.1)이 4주 단위에서도 지켜진다. 대신 지민의 중간고사 퀘스트라인은 5일 일찍 끝난다.

## 7. 앞으로

- 베타가 시작되면 매주 `pnpm sim --compare`로 실데이터를 시뮬레이션 범위와 비교 → 범위 밖 지표부터 가중치·곡선 재조정 (DEPLOY §5).
- 플레이어 정책을 실데이터에서 추정 (빼기·더 담기 비율 → `policy` 값), 페르소나를 베타 코호트로 교체.
- 회차만 바꾼 일정에 "이후 모든 회차" 범위 추가 (지금은 이번 회차 / 모든 회차).

## 8. 다시 돌리기

```bash
pnpm db:start
pnpm test:e2e personas            # 5개 여정 (P1–P3 모바일, P4–P5 데스크톱)
open test-results/personas/*/journal.md
pnpm sim                          # 4주 규칙 시뮬레이션 리포트, 수동 vs 적극 (--write → docs/SIMULATION.md)
pnpm sim --compare beta.json      # 베타 지표와 비교
```
새 페르소나는 `buildWorld()`로 세계를 만들고, **관찰 → 개선 → 단언** 순서로 여정을 추가한다.
